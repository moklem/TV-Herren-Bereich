<objective>
Add .lean() to all read-only Mongoose queries across the 9 route files to eliminate Mongoose Document hydration overhead on every GET request.

Purpose: The research confirmed 169 queries with no .lean(). Each hydrated Document carries getters, setters, change-tracking, and validation overhead — pure waste on read-only endpoints. This is the single largest source of unnecessary memory and CPU pressure.
Output: .lean() appended to all safe read-only query chains across all route files.
</objective>

  <action>
    For each of the 9 route files listed, apply the same rule as Task 1:

    PROCESS FOR EACH FILE:
    1. Read the file completely
    2. Identify all Mongoose query chains (.find(), .findOne(), .findById(), .findByIdAndUpdate with {new: true} when only reading)
    3. For each query: check if the result variable is passed ONLY to res.json() (safe) or if it has .save() / schema methods / array mutations called on it (unsafe)
    4. Add .lean() to the end of all safe query chains

    General patterns that are SAFE for .lean():
    - `const items = await Model.find({...}).populate(...).sort(...)`  followed by `res.json(items)` or `res.status(200).json({items})`
    - `const item = await Model.findById(id).populate(...)`  followed by `if (!item) return 404; res.json(item)`
    - `const item = await Model.findOne({...})` followed by returning a check result or the item as JSON

    General patterns that are UNSAFE (do NOT add .lean()):
    - Any query followed by `item.save()`
    - Any query followed by `item.fieldName.push(...)` then save
    - Any query followed by calling a method defined on the Schema (custom instance methods)
    - `Model.findByIdAndUpdate(...)` — already returns updated doc atomically, no lean needed and it may matter for chaining

    teamRoutes.js specifics: Team model likely has team.members, team.coaches arrays. Any route that modifies team membership must NOT be leaned.

    userRoutes.js specifics: User model likely has user.teams, user.achievements. Profile GET endpoints are safe. Password change, profile update routes are not.

    For all other route files (achievement, attribute, comparison, notification, progress, teamInvite, trainingPool): Apply the safe/unsafe rule consistently. When in doubt, err on the side of NOT adding .lean() — it is better to miss an optimization than to break a mutation route.

    Add .lean() at the end of query chains, before the semicolon or closing parenthesis:
    ```javascript
    // Before:
    const teams = await Team.find({ members: userId }).populate('coach', 'name').sort({ name: 1 });
    // After:
    const teams = await Team.find({ members: userId }).populate('coach', 'name').sort({ name: 1 }).lean();
    ```
  </action>
