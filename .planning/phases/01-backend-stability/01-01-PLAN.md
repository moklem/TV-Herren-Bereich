  <name>Task 1: Extend /api/health with memory data and add V8 startup log</name>
  <files>server/server.js</files>
  <action>
    1. Near the top of server.js, after the existing `require` statements, add:
       ```javascript
       const v8 = require('v8');
       ```
       Then find the first console.log or server.listen call (wherever startup logs appear) and insert:
       ```javascript
       console.log(`[Startup] V8 heap size limit: ${Math.round(v8.getHeapStatistics().heap_size_limit / 1024 / 1024)} MB`);
       ```
       This confirms NODE_OPTIONS is active on every deploy.

    2. Find the existing `/api/health` route handler (currently around line 69 in server.js). Replace the entire handler body with:
       ```javascript
       app.get('/api/health', (req, res) => {
         const mem = process.memoryUsage();
         res.status(200).json({
           status: 'ok',
           memory: {
             heapUsed: mem.heapUsed,
             heapTotal: mem.heapTotal,
             rss: mem.rss
           }
         });
       });
       ```
       Note: The status field changes from "OK" to "ok" — this is per CONTEXT.md spec. Render.com health check only verifies HTTP 200, not the body string.

    3. Remove the import of notificationScheduler from server.js:
       - Find and delete the line that does `require('./utils/notificationScheduler')` (or similar destructured import of `startNotificationScheduler`)
       - Find and delete the line that calls `startNotificationScheduler()` (research confirmed this is around line 324)
       - Do NOT touch the `startNotificationQueue` import or call — that stays.
  </action>
